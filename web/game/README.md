# web/game: the game code

This folder is the source of ss13.live's game logic: one `.ts` file per original DM file, same folder layout as tg's `code/` and `_maps/`. Edit these files directly; nothing regenerates them. To learn to read it first: [HOW-TO-READ.md](HOW-TO-READ.md).

- **Procs:** `rt.def("/type/proc/name", fn)` calls (`rt.def(path)` alone: a proc with no body, a BYOND built-in or an empty proc). `node tools/translate-tg.mjs` (run by `boot-check` and `build:static` when a file here changes) bundles them into `build/translated-tg.js`, and their paths, in order, into `build/game-types.js`: a type's proc lists come from that order (a second `rt.def` of a path overrides the first; files sorted, then top to bottom). A proc's DM argument names are its function's parameters after `f` (a leading `_` on a JS reserved name or a runtime helper's is dropped: `_in` is `in`, `_T` is `T`). Anything else goes in an optional 4th argument, an object literal of constants on the rt.def's last line: `rt.def(path, fn, gen, { args: [...], waitfor: false, hidden: true, hidePopup: true, verb: { name, category, desc, src, range, invisibility }, argTypes: [{ type, path, source }] })` (`args` where the parameters aren't the DM names, e.g. a proc that reads `args`; see ProcMeta in src/vm/json.ts). A bodiless one with meta: `rt.def(path, undefined, false, { ... })`.
- **Calling a proc by value:** `P("/proc/playsound")`, `P("/obj/item/proc/attack_self")` (the rt.def path; when a type defines one proc twice, the path names the last one). The bundler turns each into `$P[k]`, an entry of a per-file table that the VM fills once at install, so a call site costs nothing extra; the argument must be a string literal. A proc as a type var's value: `rt.procRef("/path")`.
- **Reading and writing variables by name:** write the name as a string, never a cache index. `rt.sv(f, "x")` reads `src.x`, `rt.setSv(f, "x", v)` writes it; `rt.fv(f, "x", OBJ)` reads `OBJ.x`, `rt.setFv(f, "x", OBJ, v)` writes `OBJ.x = v`. The name must be a string literal (the bundler gives each site its own cache slot and pads the lowered text so lines and columns stay; it stops with an error if a site's argument prefix spans a line break). Without a literal name the unbundled runtime versions do a plain lookup.
- **Vars as properties:** inside a proc (or tail) `this` is src. `this.x`, `o.x` and `o.x = v` read and write DM vars through the same engine path as rt.sv/rt.fv (deleted objects read null, a var of a deleted or null object is a runtime error), for every var name but runtime.ts `NOT_PROPS` (`loc`, `x`/`y`/`z`, `type`, `contents`, `key`, list members like `len`, JS ones like `length`), which aren't properties: `this.loc` is lowered to rt.sv (DM vars, below), JS ones stay rt.fv. Only on a value that is always an object or null (on a number or text `o.x` is undefined, not an error); not in a proc (or its tails) that assigns `f.src` (`src = null`: there `this` and the frame's src part ways; the rest of its file is fine), nor inside a nested `function` (its own `this`). `node tools/dt-props.mjs FILE|/proc/path` rewrites src reads and writes this way (run on all of game/ once, detranslate step 5).
- **Deleted objects:** a `del`eted object reads as null from any var, global or list item; a proc's own locals, args, `.` and usr keep it as is (detranslate step 6b dropped `live()`), and using its vars is the same runtime error as null's (counted: `WARNING deleted objects used` in boot logs).
- **Globals:** in a proc `GLOB.x` is the DM global `x` (detranslate step 9g, tg's own spelling: `GLOB.player_list`, `GLOB.SSair`; `tools/proc-calls.mjs` readableGlobal): read, `GLOB.x = v`, `GLOB.x += v`, `GLOB.x++`, unless the proc or the file binds a `GLOB`; another write (`delete`) or a GLOB outside procs stops the bundle. `node tools/dt-globals.mjs FILE` rewrites the old spelling, which stays for a bit operator's `|=` and same-named globals: `rt.gl("SSfields")` reads a global, `rt.setGl("x", v)` writes it, `rt.modGl("x", rhs, op)` is `x op= rhs`, `rt.incGl("x", d, post)` is `x++`/`x--`. The name is a string literal that must be in `_globals.ts` (a later global with the same name as an earlier one is `"name#2"`, `"name#3"`); the bundler lowers it to the index call (`$gl(872)` = `rt.glob`) padded so lines and columns stay, and stops with file:line on an unknown name. The setup in `_globals.ts` itself is not bundled this way: it uses the unbundled runtime versions (a name lookup, once at init).
- **Types and globals:** `rt.type(...)` etc., next to their type's procs; types with no procs are in a per-folder `types.ts`. Bundled separately into `build/game-types.js`.
- **Runtime errors** name the game file and line (`game/code/.../x.ts:92`), read off the JS stack when the error happens; nothing in the code tracks positions. `_dm-lines.json` holds the DM file:line each proc's lines came from (frozen at translation time, keyed by file and proc path, lines counted from the `rt.def`): tg's `/exception` file and line still use it, so the logs match BYOND's. Editing a proc can shift those DM lines; that's fine. **Codemods that change text within a line must run `node tools/remap-dm-cols.mjs <commit before the codemod>` afterwards** (it moves the columns in `_dm-lines.json`; `tests/dm-lines-cols.test.mjs` fails on stale ones). **A proc rewritten by hand** (more than a line or two changed) gets its row set to `["?",0]`: its old columns no longer sit on the new lines. `npm test` allows a little drift, so a small edit passes without it, and a big rewrite fails until you do.
- **Compile-time maps:** `_maps.ts` lists the `.dmm` files (in `../_maps/`) loaded before world/New(), one z-level each. Edit the `.dmm` files themselves (e.g. with StrongDMM); `src/vm/dmm.ts` reads them at boot. Map var edits must be constants (numbers, strings, `null`, `'file'`, `/type/path`, `list(...)`).

## Rules

- **Sleeping:** a proc that sleeps, or calls anything that might, is `function*`, and in a `function*` every call that can pause has `yield*` before it (detranslate step 9f): `..()`, a method some proc of that name is a `function*` of, a global proc that is one, or `sleep`, `alert`, `winget`, `winexists` (`tools/proc-calls.mjs` callCanWait, NATIVE_WAITS). The bundler adds `yield*` to the other calls itself, and stops on a call that can pause without one: make a proc sleep and it lists every call that now needs it. `node tools/dt-yields.mjs FILE` drops the ones that aren't needed. Calling a sleeping proc from a plain `function` breaks. When unsure, make it `function*`; that costs a little speed, never correctness. A hand-written override must be `function*` when the proc it replaces is (tgui's `ui_data`/`ui_act`/`ui_interact` are): a plain `function` there FATALs with an unhelpful stack.
- **TypeScript:** only `: Type` on parameters and variables, and the runtime imports. `translate-tg.mjs` blanks those out (so every line and column stays where it is in the bundle, which is how errors find their line) and stops on anything else (`as`, `!`, generics, interfaces, classes, other imports).
- **Parent call** (`..()` in DM): `yield* parent_proc()` (`parent_proc(a, b)`: `..(a, b)`), or the older `yield* g.callSuper(f, [args])`.
- **Proc calls** (detranslate step 8, `tools/proc-calls.mjs`): `A.name(args)` (any DM proc name but `JS_NAMES`, on `this`, an expression or a name the proc binds: `A.x()`, `f.usr.say()`; not `Math.floor()` or a file-level helper's value), `this.name(args)` on src, `name(args)` for `/proc/name` when neither its proc nor the file's top level declares a `name` of its own, `parent_proc(args)`. The bundler turns each into the old call (`rt.callName(f, A, "name", [args])` and friends, adding `f`), so they work only inside an rt.def or rt.tail; in a `function*` each needs `yield*` (the bundle stops without it: a call that must not wait for a sleep stays `rt.callName`). Named arguments are an object literal as the last argument, the positional ones first: `do_after(user, 20, { target: this })`, `A.updateappearance({ mutcolor_update: 1 })`, `new_(T("/obj/x"), loc, { name: "x" })` (plain `key: value` only: no spread, computed key, method or shorthand `{ target }`, and no object literal anywhere else in a proc call; the bundle writes back `[null, user, null, 20, "target", this], rt.Args.Named`). Calls outside procs (`_globals.ts` initialisers) keep `rt.Args.Named`. `node tools/dt-calls.mjs FILE` rewrites the old spelling (and its _dm-lines.json columns); `node tools/dt-calls-check.mjs` proves the bundle didn't change (web/README.md).
- **DM vars** (detranslate step 9a, `tools/proc-calls.mjs` readableVar): `A.x` reads and `A.x = v` writes another object's var, `this.loc` src's non-property ones (NOT_PROPS but JS ones). `x` is a var some rt.type declares, but `length`, `size`, `next`, `value`, `message`, `stack`, `caller`, `arguments`, `prototype` (those stay `rt.fv`). The bundler turns each back into rt.fv / rt.setFv / rt.sv / rt.setSv, so inside an rt.def or rt.tail `A.x`, on anything rooted at a name the proc binds (`A.loc.name`, `f.usr.client`; not bare `f`, a file helper or `Math`), is a DM read: a JS object's field there is `o["x"]`. `delete` on one stops the bundle. `node tools/dt-vars.mjs FILE` rewrites the old spelling.
- **Operators are DM's in a proc** (detranslate step 9b, `tools/proc-calls.mjs` DM_BINARY): inside an rt.def or rt.tail, `+ - * / % ** < <= > >=`, `==` and `!=` (step 9i: `isEqual`, `!isEqual`; `===` stays JS's), `-x`, `x += v` (`-= *= /= %=`) and `x++` / `--x` mean DM's and the bundler turns them into the old calls (`add(a, b)`, `rt.lt(a, b)`, `rt.neg(x)`, `rt.modify` / `rt.modSrcVar` / `rt.modField`, `rt.inc` / `rt.incSrcVar` / `rt.incField`): `null + 1` is 1, `L += x` adds to a list, a number plus text is a runtime error (write `String(n) + "s"` or `fmt`), `/ 0` too, `%` works on whole numbers. `-1` and `-Infinity` are constants. `op=` and `++` work on a local, `f.dot`, `this.x` or a DM var `o.x` (list items: rt.modAt / rt.incAt); a local's `x++` can't be used as a value (`++x` can). DM's bit operators stay calls (`rt.bitOr`: 16 bits, and lists): a plain `| & ^ << >> ~` in a proc stops the bundle. A file's own helper functions, outside procs, keep JavaScript's operators. `node tools/dt-ops.mjs FILE` rewrites the old spelling.
- **DM built-ins** (detranslate step 9c, `tools/proc-calls.mjs` DM_BUILTINS): in a proc `prob(p)` and `pick(a, b)` are DM's (the bundler writes `rt.op(f, "Prob", [], [p])`, `rt.op(f, "PickUnweighted", [2], [a, b])`), unless the proc or the file binds the name; they never wait (no `yield*`). `node tools/dt-builtins.mjs FILE` rewrites the old spelling.
- **List loops** (detranslate step 9h, `tools/proc-calls.mjs` isEachLoop): in a proc `for (M of each(L, T("/mob"))) { ... }` is DM's `for(var/mob/M in L)` (`each(L)`: untyped). M must be a local declared at the top (`let M: Value = null;`, so the collector sees it), the body a `{ block }`, not in a nested function; the bundler writes the translator's `rt.forList` / `rt.next` / `rt.endFor` on the loop's own lines, the frame's enumerator slot one past the list or range loops around it, and declares `$e`. `each()` anywhere else stops the bundle. `node tools/dt-loops.mjs FILE` rewrites the old spelling (it removes lines, moving `_dm-lines.json` rows to match).
- **Argument defaults** (detranslate step 10c): `x ??= 20;` (a bare name, a statement of its own, in a block) is DM's `var/x = 20` argument default; the bundler writes back `if (x === null) { x = 20; }`, so only null counts. `??=` anywhere else in a proc stops the bundle. `node tools/dt-defaults.mjs FILE` rewrites the old spelling.
- **new_()** (detranslate step 9k, `tools/proc-calls.mjs` isNewCall): in a proc `new_(T("/obj/x"), a, b)` is DM's `new /obj/x(a, b)` (`rt.new_(f, T, [a, b])`), `yield* new_(...)` one whose New() may sleep (`g.new_`); named arguments and var overrides keep `rt.new_(f, T, [..], rt.Args.Named)` / `rt.newOv`. `node tools/dt-new.mjs FILE` rewrites the old spelling.
- **list()** (detranslate step 9j, `tools/proc-calls.mjs` isListCall): in a proc `list(a, b)` is DM's (`rt.list(a, b)`), unless the proc or the file binds `list`. `node tools/dt-list.mjs FILE` rewrites the old spelling.
- **DM text** (detranslate step 9d): in a proc a template string is DM's embedded text: `` `${x}-punch` `` is `fmt("＀-punch", [x])` ("the" before an improper name, DM's number format). A DM macro character (U+FF01 up: `\the`, `\ref`...) in one stops the bundle: write those with `fmt`. A file helper's templates are JavaScript's. `node tools/dt-text.mjs FILE` rewrites the old spelling.
- **Bugs from 2017 tg's own code:** fix them, with a comment at the change; modern tg's fix is a good model. If compare-logs expects that runtime from the BYOND reference, update its expectation too.
- **spawn():** `rt.spawnTail(f, delay, "name", values...)`, with the body as a top-level `rt.tail("name", function* (f, ...) {...})` right after the proc. A waiting spawn is then data, which the lobby snapshot can hold. Likewise a proc asleep when the lobby snapshot is saved: its code after the sleep is a tail, started by `return yield* rt.sleepThen(f, delay, "name", [values])`. If a generator is asleep there, `build:static` stops with `world snapshot blocked`. A loop that is always asleep mid-round (the Master controller, the failsafe) sleeps with `yield* rt.sleepKeep(f, delay, "name", [values])` instead, where tail "name" is the loop's next iteration from the top, so `tools/make-snapshot.mjs` can save a round in progress.
- **Locals:** declare them at the top of the proc (`let x: Value = null;`, as the translated procs do). The bundle lists those, and the arguments the proc assigns, for the garbage collector (`f.vars`, written by `translate-tg.mjs`; one in game code stops the bundle). A `const` inside a block isn't listed: fine for a value used at once, not for an object it alone holds across a sleep or a `del`.
- **New proc:** add `rt.def("/type/path/proc/name", function* name(f) { ... }, true)` in the file for that type. Proc ids are rt.def positions, so adding or moving an rt.def means a saved snapshot no longer loads: rebuild it with `build:static`.
- **Override order:** a second `rt.def` of the same path overrides the first (its `..()` calls the first). The order is the bundle's: files sorted by path, then top to bottom. A type's verbs are listed in that order too.
- **New type:** add an `rt.type(...)` entry next to the type's procs, or in the folder's `types.ts`.
- **Deleting a type:** type ids must stay 0..n-1, so run `node tools/renumber-types.mjs` from web/ after deleting and commit its result (many files, ids only) with the deletion. A dead global's `InitGlobalNAME` may be deleted too (`global_vars/Initialize` skips a global without one); its `_globals.ts` slot stays.
- The original DM, with its comments, is /tg/station's `code/` from 2017 (not in this repo).
- **Comments:** line 1 of a file says which DM file it is based on (`// Based on /tg/station's code/game/machinery/firealarm.dm.`); `// firealarm.dm:32` above a proc is the line its DM began on (the keys of `_dm-lines.json`). Keep both when you edit.
