# web/game: the game code

This folder is the source of ss13.live's game logic: one `.ts` file per original DM file, same folder layout as tg's `code/` and `_maps/`. Edit these files directly; nothing regenerates them. To learn to read it first: [HOW-TO-READ.md](HOW-TO-READ.md).

- **Procs:** `rt.def("/type/proc/name", fn)` calls (`rt.def(path)` alone: a proc with no body, a BYOND built-in or an empty proc). `node tools/translate-tg.mjs` (run by `boot-check` and `build:static` when a file here changes) bundles them into `build/translated-tg.js`, and their paths, in order, into `build/game-types.js`: a type's proc lists come from that order (a second `rt.def` of a path overrides the first; files sorted, then top to bottom). A proc's DM argument names are its function's parameters after `f` (a leading `_` on a JS reserved name is dropped: `_in` is `in`). Anything else goes in an optional 4th argument, an object literal of constants on the rt.def's last line: `rt.def(path, fn, gen, { args: [...], waitfor: false, hidden: true, hidePopup: true, verb: { name, category, desc, src, range, invisibility }, argTypes: [{ type, path, source }] })` (`args` where the parameters aren't the DM names, e.g. a proc that reads `args`; see ProcMeta in src/vm/json.ts). A bodiless one with meta: `rt.def(path, undefined, false, { ... })`.
- **Calling a proc by value:** `P("/proc/playsound")`, `P("/obj/item/proc/attack_self")` (the rt.def path; when a type defines one proc twice, the path names the last one). The bundler turns each into `$P[k]`, an entry of a per-file table that the VM fills once at install, so a call site costs nothing extra; the argument must be a string literal. A proc as a type var's value: `rt.procRef("/path")`.
- **Reading and writing variables by name:** write the name as a string, never a cache index. `rt.sv(f, "x")` reads `src.x`, `rt.setSv(f, "x", v)` writes it; `rt.fv(f, "x", OBJ)` reads `OBJ.x`, `rt.gv(f, "x", OBJ)` the same with OBJ read through `live()` first, `rt.setFv(f, "x", OBJ, v)` writes `OBJ.x = v`. The name must be a string literal (the bundler gives each site its own cache slot and pads the lowered text so lines and columns stay; it stops with an error if a site's argument prefix spans a line break). Without a literal name the unbundled runtime versions do a plain lookup.
- **Globals by name:** `rt.gl("SSfields")` reads a global, `rt.setGl("x", v)` writes it, `rt.modGl("x", rhs, op)` is `x op= rhs`, `rt.incGl("x", d, post)` is `x++`/`x--`. The name is a string literal that must be in `_globals.ts` (a later global with the same name as an earlier one is `"name#2"`, `"name#3"`); the bundler lowers it to the index call (`$gl(872)` = `rt.glob`) padded so lines and columns stay, and stops with file:line on an unknown name. The setup in `_globals.ts` itself is not bundled this way: it uses the unbundled runtime versions (a name lookup, once at init).
- **Types and globals:** `rt.type(...)` etc., next to their type's procs; types with no procs are in a per-folder `types.ts`. Bundled separately into `build/game-types.js`.
- **Runtime errors** name the game file and line (`game/code/.../x.ts:92`), read off the JS stack when the error happens; nothing in the code tracks positions. `_dm-lines.json` holds the DM file:line each proc's lines came from (frozen at translation time, keyed by file and proc path, lines counted from the `rt.def`): tg's `/exception` file and line still use it, so the logs match BYOND's. Editing a proc can shift those DM lines; that's fine. **Codemods that change text within a line must run `node tools/remap-dm-cols.mjs <commit before the codemod>` afterwards** (it moves the columns in `_dm-lines.json`; `tests/dm-lines-cols.test.mjs` fails on stale ones). **A proc rewritten by hand** gets its row set to `["?",0]` (its old columns no longer sit on the new lines, so `npm test` fails until you do).
- **Compile-time maps:** `_maps.ts` lists the `.dmm` files (in `../_maps/`) loaded before world/New(), one z-level each. Edit the `.dmm` files themselves (e.g. with StrongDMM); `src/vm/dmm.ts` reads them at boot. Map var edits must be constants (numbers, strings, `null`, `'file'`, `/type/path`, `list(...)`).

## Rules

- **Sleeping:** a proc that sleeps, or calls anything that might, is `function*`, and every call to it uses `yield*`. Calling a sleeping proc from a plain `function` breaks. When unsure, make it `function*`; that costs a little speed, never correctness. A hand-written override must be `function*` when the proc it replaces is (tgui's `ui_data`/`ui_act`/`ui_interact` are): a plain `function` there FATALs with an unhelpful stack.
- **TypeScript:** only `: Type` on parameters and variables, and the runtime imports. `translate-tg.mjs` blanks those out (so every line and column stays where it is in the bundle, which is how errors find their line) and stops on anything else (`as`, `!`, generics, interfaces, classes, other imports).
- **Parent call** (`..()` in DM): `yield* g.callSuper(f, [args])`.
- **Bugs from 2017 tg's own code:** fix them, with a comment at the change; modern tg's fix is a good model. If compare-logs expects that runtime from the BYOND reference, update its expectation too.
- **spawn():** `rt.spawnTail(f, delay, "name", values...)`, with the body as a top-level `rt.tail("name", function* (f, ...) {...})` right after the proc. A waiting spawn is then data, which the lobby snapshot can hold. Likewise a proc asleep when the lobby snapshot is saved: its code after the sleep is a tail, started by `return yield* rt.sleepThen(f, delay, "name", [values])`. If a generator is asleep there, `build:static` stops with `world snapshot blocked`. A loop that is always asleep mid-round (the Master controller, the failsafe) sleeps with `yield* rt.sleepKeep(f, delay, "name", [values])` instead, where tail "name" is the loop's next iteration from the top, so `tools/make-snapshot.mjs` can save a round in progress.
- **New proc:** add `rt.def("/type/path/proc/name", function* name(f) { ... }, true)` in the file for that type. Proc ids are rt.def positions, so adding or moving an rt.def means a saved snapshot no longer loads: rebuild it with `build:static`.
- **Override order:** a second `rt.def` of the same path overrides the first (its `..()` calls the first). The order is the bundle's: files sorted by path, then top to bottom. A type's verbs are listed in that order too.
- **New type:** add an `rt.type(...)` entry next to the type's procs, or in the folder's `types.ts`.
- **Deleting a type:** type ids must stay 0..n-1, so run `node tools/renumber-types.mjs` from web/ after deleting and commit its result (many files, ids only) with the deletion. A dead global's `InitGlobalNAME` may be deleted too (`global_vars/Initialize` skips a global without one); its `_globals.ts` slot stays.
- The original DM, with its comments, is /tg/station's `code/` from 2017 (not in this repo).
